---
description: Process a meeting summary to create documentation and key takeaways
---

1.  **Analyze the Meeting Summary**:
    *   Read the user-provided meeting summary carefully.
    *   Identify the main topics, new concepts, action items, and any code snippets or configuration details mentioned.

2.  **Determine Documentation Location**:
    *   Explore the `e:\Git\AzureTraining` repository to find the most relevant existing folders (e.g., `Concepts`, `Labs`, specific project folders).
    *   If a relevant folder exists, plan to add a new file there or update an existing one.
    *   If no relevant folder exists, plan to create a new logical directory structure (e.g., `NewTopic/README.md` or `NewTopic/Concepts/...`).

3.  **Draft Documentation**:
    *   Create new markdown files or update existing ones.
    *   Use clear headings, code blocks for technical details, and standard markdown formatting.
    *   Ensure the content is well-structured and easy to understand, following the style of existing documentation in the repo.
    *   *Self-Correction*: Check if the new files need to be linked in any `README.md` files (like the root README or section READMEs) for navigation. If so, update them.

4.  **Generate Key Takeaways**:
    *   Summarize the most important points from the meeting into a concise list of "Key Takeaways".
    *   Post these takeaways in the chat for the user to copy.

5.  **Review**:
    *   Present the created/updated files to the user for review.
    *   Ask if any adjustments are needed.
