# Introduction to Git and CLI Concepts

## Git vs. GitHub
It is important to distinguish between Git and GitHub:
-   **Git**: The CLI-based tool used for version control. It runs locally on your machine.
-   **GitHub**: A cloud-based hosting platform for Git repositories. (Azure DevOps Repos is another example of a hosting platform).

## Git as a CLI
Git is a Command Line Interface (CLI) tool. Conceptually, it is similar to cloud CLIs (like Azure CLI or AWS CLI) in that you run commands to manage workflows and operations.

## Installation
-   **Download**: Download Git for your OS (Windows/Mac) from the official website.
-   **Install**: Install using default settings.

## Methods for Using Git
There are three main ways to interact with Git:
1.  **Git GUI**: A graphical user interface.
2.  **Git Bash**: A terminal application that provides a bash-like experience on Windows. **This is the recommended method for practice.**
3.  **Git CMD**: A standard Windows command prompt with Git commands.

## Purpose of Version Control Systems (VCS)
Git is a Version Control System (VCS) or Source Code Control (SCC).

### Why do we need VCS?
Without a VCS (e.g., using shared folders), teams face several issues:
-   **Overwriting**: Team members might overwrite each other's work.
-   **Conflicts**: Simultaneous changes are hard to merge.
-   **No History**: There is no reliable history of who changed what and when.

VCS solves these problems by tracking changes, managing conflicts, and maintaining a history of all modifications, enabling teams to work in parallel efficiently.
